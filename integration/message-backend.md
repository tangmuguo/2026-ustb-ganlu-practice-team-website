# 互动留言板后端对接文档

## 1. 概述

本文档对应互动留言板后端改造任务，实现游客可读、分级权限留言 / 删除、请求体身份防伪造、N+1 查询优化等能力，所有接口统一返回 {code, message, content} 格式。

核心改造点

1. 身份可信：新增 / 删除接口均从认证上下文取登录用户 ID，完全不信任请求体中的用户 ID 字段
2. 权限分级：level 0/1/2 均可留言 / 回复；仅 level 0/1 可执行逻辑删除
3. 软删除机制：全程使用 status 字段逻辑删除，不物理清除历史审计数据
4. 性能优化：分页列表通过批量查询解决回复、用户信息的 N+1 问题

## 2. 接口总览

表格

| **接口路径** | **请求方式** | **权限要求** | **功能说明** |
| --- | --- | --- | --- |
| /message/list | GET | 游客开放 | 分页获取公开留言列表（仅返回正常状态数据） |
| /message/add | POST | 需登录（level 0/1/2） | 新增留言 |
| /message/addReply | POST | 需登录（level 0/1/2） | 对指定留言新增回复 |
| /message/delete | POST | 需登录（仅 level 0/1） | 逻辑删除指定留言 |
| /message/deleteReply | POST | 需登录（仅 level 0/1） | 逻辑删除指定回复 |

## 3. 接口详细说明

### 3.1 留言分页列表

* 路径：GET /message/list
* 权限：游客可访问
* 查询参数：

表格

| **参数名** | **类型** | **约束** | **说明** |
| --- | --- | --- | --- |
| page | int | ≥1 | 页码，默认 1 |
| pageSize | int | 1~50 | 每页条数，默认 10 |

### 3.2 新增留言

* 路径：POST /message/add
* 权限：需登录（level 0/1/2 均允许）
* 请求体：

json
{

"content": "留言正文内容"

}

* 字段约束：content 首尾去空格后长度 1~500 字符，纯文本存储
* 成功返回：code=200，content 返回新增留言的 ID

### 3.3 新增回复

* 路径：POST /message/addReply
* 权限：需登录（level 0/1/2 均允许）
* 请求体：

json
{
"messageId": 1,
"content": "回复正文内容"
}

* 字段约束：content 首尾去空格后长度 1~300 字符；messageId 必须为有效且未删除的留言 ID

### 3.4 删除留言

* 路径：POST /message/delete
* 权限：仅 level 0/1 可操作，level 2 返回 403
* 请求体：

json
{
"id": 1
}

* 说明：逻辑删除，仅更新留言 status=0；留言删除后公开列表不再展示其下回复，底层回复数据保留

### 3.5 删除回复

* 路径：POST /message/deleteReply
* 权限：仅 level 0/1 可操作，level 2 返回 403
* 请求体：

json
{
"id": 1
}

* 说明：逻辑删除，仅更新回复 status=0

## 4. 统一错误码说明

表格

| **HTTP 状态码** | **code** | **业务场景** |
| --- | --- | --- |
| 200 | 200 | 请求成功 |
| 400 | 400 | 参数非法：空内容、内容超长、分页参数越界、无效资源 ID |
| 401 | 401 | 未登录：游客调用需登录的接口 |
| 403 | 403 | 权限不足：level 2 用户调用删除接口、伪造用户 ID 越权 |
| 404 | 404 | 资源不存在：留言 / 回复 ID 无效、对应资源已删除 |

## 5. 数据库补丁说明

补丁文件

路径：database/patches/20\_message\_board.sql

执行顺序

1. 在已导入 ganlu.sql 的数据库中，增量执行本补丁
2. 先执行孤儿数据核查语句，确认无效数据量后，按需执行清理
3. 索引创建语句自带幂等判断，重复执行不会报错
4. 外键约束为可选项，团队确认数据完整性要求后再启用

核心约束

* 不 DROP 任何原表、不清除已有历史留言数据
* 全程使用 status 逻辑软删除，无物理删除操作
* 外键统一为 RESTRICT 模式，禁止级联物理删除，保护历史审计数据
* 新增组合索引匹配业务查询路径，优化分页与批量查询性能

## 6. 测试账号说明

表格

| **账号角色** | **用户等级 level** | **权限范围** |
| --- | --- | --- |
| 管理员 | 0 | 留言、回复、删除留言 / 回复 |
| 团队成员 | 1 | 留言、回复、删除留言 / 回复 |

## 7. 补充业务规则

1. 排序规则：所有列表统一按 create\_time DESC, id DESC 排序，id 作为第二排序键保证分页稳定性
2. 用户删除展示策略：用户被删除后，其历史留言、回复数据完整保留，不做级联删除；列表页正常展示内容，用户信息缺失时显示用户 ID 占位
3. N+1 优化说明：分页列表通过「1 条留言分页查询 + 1 条回复批量查询 + 1 条用户批量查询」实现，杜绝逐行查询，数据量增大时性能稳定
4. 内容安全：所有正文以纯文本存储与返回，不存储、不解析 HTML 内容；业务日志不打印完整留言正文与用户敏感信息
