## 具体实现要求

1. 游客能查看留言和回复，但输入区显示“登录后参与互动”的按钮。
2. 管理员、团队账号和学生账号都能发布留言与回复，不再维持“只有学生留言、只有团队回复”的旧限制。
3. `level=0` 管理员和 `level=1` 团队账号显示删除按钮，均可删除留言和回复；`level=2` 学生账号不能看到删除按钮。删除权限不按内容是否本人发布区分。
4. 留言输入限制 1～500 字，回复限制 1～300 字，实时显示剩余字数；提交前 `trim()`。
5. 提交过程中按钮进入 loading，防止双击重复提交；成功后只清空对应输入框并刷新当前页。
6. 删除必须使用 `ElMessageBox.confirm` 二次确认。删除当前页最后一条后，如页码超出，应自动回到上一页。
7. 请求失败时不要清空未提交内容；401 引导登录，403 显示无权限，其他错误允许重试。
8. 留言和回复都显示发布者名称、账号类型/团队名、时间和正文。正文使用插值渲染，禁止未经清洗的 `v-html`。
9. 页面需有首屏加载骨架、无留言空状态、接口失败状态；不要只弹一个消息后留下空白页面。
10. 分页时保留当前滚动体验；小屏下用户名、时间和操作按钮允许换行，不能横向溢出。
11. 移除 `console.log` 和把未登录默认成某个虚构 level 的逻辑，改为明确的 `isLoggedIn`、`canDelete` 等计算属性；`canDelete` 仅对 `level=0/1` 为真。

## 接口约定

- `GET /message/list?page=1&pageSize=10`
- `POST /message/add`，请求 `{ "content": "..." }`
- `POST /message/addReply`，请求 `{ "messageId": 1, "content": "..." }`
- `POST /message/deleteMessage`，请求 `{ "id": 1 }`
- `POST /message/deleteReply`，请求 `{ "id": 1 }`

用户身份不出现在请求体中。成功按统一 `code=200` 判断；列表数据仍为 `content.messages` 和 `content.total`。

## 验收标准

- 游客只读；管理员、团队和学生均能留言、回复；管理员和团队能删除，学生不能删除。
- 团队账号删除留言/回复成功；学生账号手工构造删除请求时，前端能显示后端 403，而不是误报成功。
- 留言和回复的空值、超长值、重复点击均被正确处理。
- 1、10、11 条留言时分页显示正确，删除跨页不出现空白死页。
- 375px 手机宽度无横向滚动条。
- `npm run build` 通过，控制台无未处理 Promise 错误。
