## 认证和权限基础要求

1. 登录成功返回短期 Bearer Token 和不含密码的用户信息；后端接口从 Token 获取当前用户。
2. 使用 BCrypt 保存新密码。为兼容旧明文数据，可在旧用户首次成功登录后自动升级为 BCrypt；不得在 SQL 中批量生成可预测密码。
3. `UserAction` 不能继续把数据库密码直接比对并把完整实体当登录会话；Token 过期/伪造均返回 401。
4. 前端只根据角色控制可见性，最终权限必须在后端接口再次校验。
5. 注册 DTO 不接受客户端传入 level；团队注册固定 level=1，学生注册固定 level=2。
6. 团队注册字段：登录账号、团队简称、支教地、支教小学、手机号、密码/确认密码。学生注册字段：账号、真实姓名、所属小学、年级、手机号、密码/确认密码。
7. 用户名、手机号设置唯一约束；返回前始终清空密码字段。
8. 学生账号注册是公开接口，游客和任意登录角色均可访问；注册结果始终由后端固定为 level=2。学生账号管理只允许 level=0/1，level=2 不可管理学生账号。

## 公共页面要求

### 首页

保留现有后端轮播图和新闻数据，重新组织为：轮播/主视觉、甘露简介、课件/团队/互动/AI 四个入口、最新动态、加入甘露 CTA。不要继续依赖不存在的 Font Awesome 图标；优先使用现有 Element Plus 图标。

### 关于甘露

展示经负责人确认的甘露支教简介、历史时间线、服务地区和理念。没有确认的年份/数字使用可维护的数据结构或明显待确认标记，不编造内容。

### 联系我们

展示确认后的地址、电话、邮箱和联系说明；不要从当前 Footer 直接复制未经确认的个人联系方式到多个文件。

### 加入甘露

提供志愿者在线报名，建议字段：姓名、手机、学校/单位、年级或专业、意向地区、擅长方向、自我介绍、隐私同意。后端校验手机号、长度、重复提交并记录状态 `PENDING/CONTACTED/ACCEPTED/REJECTED`；管理员可查看和更新状态，公开端不能读取报名列表。
