# 王嘉阳：团队风采核心后端任务单

## 任务目标

建立团队风采的核心数据关系和公开/管理接口，使管理员可以按年份创建小队，公开端可以按“年份 → 小队 → 详情”查询。重点修复当前 `team` 表未被公开页使用、`team_page` 实体和 SQL 字段不一致、团队 ID 与用户 ID 混用的问题。

## Windows 11 环境

安装 Git for Windows、64 位 Eclipse Temurin JDK 8、IntelliJ IDEA Community、MySQL Server 8.0、MySQL Workbench 和 Postman/Apifox。

```powershell
java -version
mysql --version
cd backend
.\mvnw.cmd spring-boot:run
```

先在本机新建 `ganlu` 数据库并导入根目录 `ganlu.sql`，只使用本地账号密码。

## 数据库修改要求

在 `10_team_core.sql` 中用增量 `ALTER/UPDATE` 迁移，不要先 DROP 表：

1. `team` 增加 `owner_user_id`、`region`、`school`、`description`、`cover_url`、`status`、`created_at`、`updated_at`。
2. `year` 改为 4 位年份可验证字段；增加 `(year,name)` 唯一约束和 `year/status` 索引。
3. `team_page` 统一为 `team_id`，建立对 `team.id` 的外键，并保证一个 team 最多一个详情页。
4. 对旧数据先备份、映射再增加约束；脚本重复执行时给出清晰说明，不静默丢数据。
5. `owner_user_id` 必须指向 `level=1` 的团队账号，业务层还要再次校验，不能只依赖外键。

## 接口要求

公开接口：

- `GET /teams/years`：年份倒序，返回年份、封面、已发布小队数。
- `GET /teams?year=2025&page=1&size=12`：只返回已发布小队。
- `GET /teams/{teamId}`：返回小队基本信息和 pageId；内容列表由李嘉辉的服务补充或前端另行获取。

管理员接口：

- `POST /admin/teams`
- `PUT /admin/teams/{teamId}`
- `DELETE /admin/teams/{teamId}`：实际执行归档，不直接物理删除已有内容的团队。

创建/修改时校验年份、名称、地区、学校、负责人账号和状态。只有管理员可创建、发布、归档团队；身份从赵友为提供的认证上下文获取。

现有 `/user/teams` 继续用于“团队账号管理”，不要拿它代替新的团队业务接口。

## 验收标准

- 管理员可创建 2025 年的小队并绑定一个 level=1 账号；重复年份+名称被拒绝。
- 游客按年份只能查到 `PUBLISHED` 小队，草稿/归档不出现。
- 详情接口以 teamId 查询，任何 SQL 不再用传入 teamId 去匹配 `userId`。
- 更新团队不会创建第二个 team_page；归档后公开列表消失但数据仍保留。
- 非管理员调用管理接口返回 403。
- 增量 SQL 能在导入原 `ganlu.sql` 后执行，原有用户和风采记录不被直接删除。
- `.\mvnw.cmd test` 通过。
