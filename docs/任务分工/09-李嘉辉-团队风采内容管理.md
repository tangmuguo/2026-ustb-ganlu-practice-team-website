## 数据与状态要求

1. 所有内容以 `team_id` 或 `page_id` 关联，不再把 `userId` 当团队主键。
2. 图片内容类型至少包括：`MEMBER`、`REGION_PHOTO`、`TEACHING_PHOTO`。
3. 文字内容类型至少包括：`HONOR`、`CLASS_LOG`。
4. 新增 `team_media` 保存视频和其他附件：文件名、相对路径、MIME、大小、上传者、teamId、关联内容、状态、时间。
5. 状态统一为 `PENDING`、`PUBLISHED`、`REJECTED`、`ARCHIVED`；团队提交默认 `PENDING`，管理员审核后公开。
6. `11_team_content.sql` 以增量方式把旧图片/文字尽量映射到 team/page；不能直接 DROP 旧表。无法自动映射的数据输出待人工处理查询。

## 权限与文件要求

1. 团队账号只能给自己绑定的 teamId 上传、查看和删除后台记录；管理员可为任意团队上传，并可查看、删除、发布、驳回、归档任意团队内容；学生账号不能进入内容管理接口。
2. 后端从 Token 获取当前用户，校验其是否为 team.owner_user_id；请求体不接受可信 userId。
3. 图片允许 JPG/JPEG/PNG/WebP，建议最大 10MB；视频允许 MP4/MOV，其他附件允许 PDF/DOC/DOCX/PPT/PPTX/ZIP，单文件最大 200MB。
4. 服务端同时检查扩展名、MIME、文件头和大小，文件名使用安全随机名，防止 `../` 路径穿越和同名覆盖。
5. 公开端对图片返回可预览 URL；视频和普通文件只返回受控下载地址，不提供 `<video>` 播放 URL。
6. 团队账号可删除自己绑定团队的内容，包括已发布内容；管理员可删除任意团队内容。删除采用逻辑删除或归档并保留审计时间，前端必须二次确认。
7. 上传接口失败时清理孤立临时文件；数据库失败不能留下无人管理的文件。

## 建议接口

团队端：

- `GET /team-content/mine`
- `POST /team-content/{teamId}/members`
- `POST /team-content/{teamId}/photos`
- `POST /team-content/{teamId}/logs`
- `POST /team-content/{teamId}/honors`
- `POST /team-content/{teamId}/media`
- `POST /team-content/{type}/{id}/delete`：level=1 仅限自己团队，level=0 可操作任意团队；后端执行逻辑删除或归档。

公开端：

- `GET /team-content/public/{teamId}`：只返回 PUBLISHED。
- `GET /team-content/media/{mediaId}/download`：视频/附件下载，响应设置安全文件名。

管理员端：

- `GET /admin/team-content?status=PENDING`
- `POST /admin/team-content/{type}/{id}/publish`
- `POST /admin/team-content/{type}/{id}/reject`

## 验收标准

- 团队 A 不能给团队 B 上传或查看后台内容，即使手工替换 URL 中 teamId。
- 团队 A 只能删除团队 A 的照片、日志和荣誉，不能删除团队 B 的内容；管理员可上传、删除任意团队内容。
- 新内容提交后公开页不可见，管理员发布后可见；驳回内容显示原因但不公开。
- 成员照、两类支教照片、日志、荣誉、视频、PDF 各完成一次上传测试。
- 视频公开端只有下载按钮，浏览器中不出现视频播放器。
- 非法扩展名、伪装 MIME、超大文件、路径穿越文件名被后端拒绝。
- 旧数据迁移不丢失，公开查询只按 teamId/pageId。
- `npm run build`、`.\mvnw.cmd test` 通过。
