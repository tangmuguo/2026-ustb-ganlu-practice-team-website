# 乔轩轲：AI 小助手前端任务单

## 任务目标

新增与现有网站风格一致的 AI 小助手页面，为登录用户提供多轮文字问答。前端只调用本项目后端，绝不能直接请求 DeepSeek 或保存 API Key。

## Windows 11 环境

安装 Git for Windows、VS Code、Node.js `22.12+`、Chrome/Edge，以及 “Vue - Official” 扩展。

```powershell
cd frontend
npm ci
npm run dev
```

联调前确认后端 `http://localhost:8080/ai/chat` 可用。

## 需要新增的文件

- `frontend/src/views/AiAssistant.vue`：AI 小助手整页容器。
- `frontend/src/components/ai/AiMessageBubble.vue`：用户/助手消息气泡。
- `frontend/src/components/ai/AiComposer.vue`：输入框、发送、停止/清空按钮。
- `frontend/src/components/ai/AiWelcome.vue`：欢迎语和示例问题。
- `frontend/src/apis/aiAPI.js`：封装 `/ai/chat` 请求。
- `frontend/src/stores/aiStore.js`：当前会话状态，使用 Pinia；只持久化必要内容。
- `docs/integration/ai-frontend.md`：提供给赵友为的路由、菜单与接口说明。

## 允许参考但不直接修改的文件

- `frontend/src/views/MessageBoard.vue`：参考 Element Plus 表单和反馈方式。
- `frontend/src/stores/userStore.js`：读取登录状态。
- `frontend/src/utils/http.js`：使用统一 Axios 实例，不自行再建固定 localhost 客户端。

共享的 `router/index.js`、`Top.vue`、`path.js` 由赵友为合并，你只提供需要新增的 `/ai` 路由和菜单项。

## 具体实现要求

1. 页面包含标题、用途说明、对话区、输入区和示例问题；文案说明“回答仅供学习参考，不提交学生隐私信息”。
2. 支持多轮对话，把当前会话最近最多 20 条消息发给后端；单次输入去除首尾空格后为 1～2000 字。
3. 请求中只发送 `role` 和 `content`，不发送 API Key、模型名、userId 或权限等级。
4. 请求期间禁用重复发送，显示“正在思考”；失败时保留用户输入并提供重试，不要直接清空会话。
5. 回车发送、`Shift+Enter` 换行；手机端输入区不遮住最后一条消息。
6. 提供“新对话/清空”并进行二次确认。默认只在 `sessionStorage` 或当前 Pinia 会话中保存，不把儿童信息长期写入浏览器。
7. 助手返回内容按纯文本显示并保留换行。不要使用未经清洗的 `v-html`；本轮也不要为了 Markdown 引入重量级编辑器。
8. 未登录访问时显示登录引导，由最终路由守卫再做强制控制。
9. 首版按非流式 JSON 接口完成。只有陈家顺的非流式接口通过验收后，才可协商 SSE 流式加分项。

## 接口合同

请求：

```json
{
  "messages": [
    { "role": "user", "content": "给三年级学生解释什么是光合作用" }
  ]
}
```

读取成功响应的 `content.answer`。对 400 显示输入提示，对 401 引导登录，对 429 显示“请求较多，请稍后再试”，对 502/504 显示“AI 服务暂时不可用”。

## 验收标准

- 登录用户能完成至少 3 轮连续问答。
- 快速连点发送不会产生重复请求。
- 空文本、2001 字、401、429、超时、断网都有明确反馈。
- 刷新后不会把密钥或完整敏感会话写进 Local Storage。
- 375px、768px、桌面端布局正常，长回复可滚动且不会撑破页面。
- 项目中搜索不到 `DEEPSEEK_API_KEY`、`api.deepseek.com` 或真实 Key 的前端引用。
- `npm run build` 通过。
