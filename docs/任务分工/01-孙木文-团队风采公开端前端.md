# 孙木文：项目总负责人兼团队风采公开端前端任务单

## 任务目标

作为项目总负责人，负责创建初始项目和团队共享文件空间，每天统一审核 Pull Request，并总览项目范围、人员分工、阶段进度、跨模块协作、风险和最终交付；同时把现有单层团队卡片页改造成 PDF 要求的“年份 → 当年小队 → 小队详情”三级公开页面，并统一展示队员、荣誉、支教地区照片、支教情况照片、课堂日志及可下载附件。具体开发任务只负责公开浏览端，不负责上传和管理员审核。

## 项目总负责人职责

1. 创建初始项目、Git 仓库、主分支、基础目录和团队共享文件空间，设置成员权限并提交初始基线。
2. 明确项目总体目标、交付范围、任务优先级、里程碑和验收标准，并维护全局进度视图。
3. 定期收集各成员进展、风险和依赖，协调前后端、数据、接口、页面和集成工作的衔接。
4. 每天审核成员提交的 Pull Request，检查任务范围、代码质量、测试记录、接口影响和合并冲突；审核通过后方可合并。
5. 对跨模块冲突、需求取舍、计划调整和影响最终交付的事项进行统筹，并作最终决定。
6. 组织阶段检查、总联调和最终验收，统一把关功能完整性、质量和交付材料。

上述职责侧重全局管理、项目初始化和代码审核，不替代各成员完成其具体模块；赵友为在孙木文创建的初始项目和共享文件体系上，继续承担基础设施与技术总集成的执行工作。

## 具体实现要求

1. 年份页展示封面、年份和当年小队数量；点击进入该年度页面。
2. 年度小队页展示每个小队的名称、支教地区、学校、封面和简介；点击进入详情。
3. 详情页顺序固定为：团队概况、队员、荣誉成就、支教地区照片、教学互动照片、课堂日志、其他附件。
4. 页面公开内容只显示后端返回的 `PUBLISHED` 数据，不显示上传和删除按钮。
5. 视频和普通文件只能显示“下载”，不得嵌入视频播放器；图片可在站内预览。
6. 所有内部跳转使用 `router.push`/`RouterLink`，不要写会整页刷新的普通 `<a href>`。
7. 桌面端、平板和 375px 手机宽度均可用；卡片高度不依赖内容完全相同。
8. 文本使用 Vue 插值渲染，不使用未经清洗的 `v-html`。
9. 保留现有蓝色主视觉，但减少详情页固定导航和紫色整页背景造成的割裂感，与首页公共布局一致。

## 接口依赖

由王嘉阳提供：

- `GET /teams/years`
- `GET /teams?year=2025`
- `GET /teams/{teamId}`

由李嘉辉提供团队详情中的内容列表。前端只认 `teamId/pageId`，不得回退到 `userId` 查询。

路由建议为 `/fengcai`、`/fengcai/:year`、`/fengcai/team/:teamId`。不要直接编辑共享的 `frontend/src/router/index.js`，把路由片段交给赵友为进行技术合并，并保留旧详情地址的兼容跳转建议。

## 验收标准

- 至少用 2 个年份、每年 2 个小队验证三级跳转。
- 直接刷新详情 URL 不丢失团队名称或内容。
- 无图片、无日志、接口 404/500 时都有明确状态。
- 图片预览正常，视频只下载不在线播放。
- 游客可浏览，页面中没有团队成员上传入口。
- `npm run build` 通过，浏览器控制台无报错。

## 交付边界

具体开发边界仍为：不直接承担路由、顶部导航、全局 Axios、总 SQL 的技术合并，不负责上传页面和审核后台。完成后把接口字段清单、三张页面截图、测试记录交给赵友为进行技术合并；作为项目总负责人，孙木文每天审核相关 Pull Request，同时汇总全员进度、风险、联调结果和验收结论，对最终交付统一把关。
