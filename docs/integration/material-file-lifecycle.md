# 课件文件生命周期联调说明

## 本轮解决的问题

- 有效课件的封面、原件、预览路径会一起参加迁移预检；同一物理路径被多条有效课件引用时，预检以 `SHARED_MATERIAL_FILE_PATH` 阻断；任一课件文件与团队图片、Banner、News、User 共享时，以 `CROSS_DOMAIN_SHARED_PATH` 阻断。
- 删除课件会先锁定记录，在同一数据库事务中软删除并为每个非空的本地封面、原件、预览写入持久化删除任务。即使删除当时仍有共享引用也不能丢弃任务；是否删除物理文件统一由提交后的处理器复核，避免两个共享课件并发删除后没有任务收尾。
- 课件任务、孤儿恢复任务和公共图片任务共用同一套规范化物理路径引用查询，统一检查有效课件、团队图片、Banner、News、User 和公共图片资产账本。这样无论先删除课件还是先删除公共图片，另一业务仍在使用时都不会误删文件。
- 公共图片任务发现仍有公共业务引用时，会保留资产账本和配额，供最后一条业务记录删除时再次收尾；只剩课件引用或另一个公共资产账本时，会清理当前账本和配额但保留物理文件。最后一个引用消失后，后续任务会删除物理文件并清理最后的账本。
- 删除任务执行时再次确认课件已删除，并按上述统一查询复核全部引用。仍被引用的文件会保留；文件不存在按幂等成功处理；删除失败会保留任务、错误、次数和下次重试时间。
- 创建课件不再搬走暂存文件。正式路径在写文件前先登记 `COURSE_ORPHAN` 恢复任务，再复制文件；提交成功后才消费暂存凭证。回滚、提交失败或进程中断后，恢复任务会清理无有效引用的正式目录孤儿文件。

## 部署前必须执行

1. 完整备份数据库和上传目录，并在隔离的备份副本中恢复。
2. 按 `database/patches/README.md` 的顺序执行补丁，`30_material_center.sql` 后紧接 `31_material_file_lifecycle.sql`。
3. 如果补丁 31 列出课件内部共享路径或课件与公共图片业务的跨生命周期共享并主动报错，立即停止。对列表中的每条有效课件复制出独立文件，更新对应的 `cover_path`、`original_file_path` 或 `preview_file_path`，再重跑补丁。
4. 启动后调用管理员公共图片预检接口。只有报告中不存在 `SHARED_MATERIAL_FILE_PATH` 且原有公共图片检查通过，才能继续联调。
5. 在备份副本演练：两条课件共享封面、共享原件、两者都共享；删除其中一条后，另一条仍能显示、下载和预览。未拆分前，预检必须拒绝通过。
6. 检查管理员文件删除任务列表。故障注入后，失败任务必须保留且可手动重试；禁止直接删除任务表记录或手工删除仍有有效引用的文件。

## 故障验收

- 模拟数据库提交失败：课件暂存文件和凭证仍在，正式目录文件最终被 `COURSE_ORPHAN` 任务清理。
- 模拟创建进程在复制后中断：重启并等待任务扫描，未被有效课件引用的文件最终消失。
- 模拟物理删除失败：课件保持软删除，任务进入 `FAILED` 并可重试，其他有效课件文件不受影响。
- 模拟任务执行中断和服务重启：再次执行同一任务结果一致；文件已不存在也能正常收敛。
- 模拟两条共享课件同时删除：两个事务都必须留下角色任务；提交后任务扫描最终删除已无有效引用的文件。
- 模拟课件与公共图片共享物理路径：分别按“先删课件、后删公共图片”和“先删公共图片、后删课件”执行；第一次删除后文件必须仍存在，最后一个引用删除后文件和对应资产账本必须最终清理。
