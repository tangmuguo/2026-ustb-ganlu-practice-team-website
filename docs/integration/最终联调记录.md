## 本轮已集成

- 网站公共页面、统一页头页脚、移动端菜单、404、路由和角色入口。
- 登录、Bearer Token、服务端角色校验、BCrypt 新密码和旧明文密码首次成功登录后自动升级。
- 团队/学生注册字段校验，用户角色由后端固定，用户名和手机号唯一约束。
- 团队风采公开前端与核心后端、AI 前后端、课件中心、留言板前端。
- 在正式成员成果尚不可见时补齐留言板后端临时最小实现；方亦琳的正式实现现已在依赖 PR #10，等待孙木文联调取舍。
- 数据库、上传目录、LibreOffice、跨域、JWT 和 DeepSeek 的环境变量配置。
- 首次管理员安全初始化：仅在数据库没有管理员且显式提供环境变量时创建，密码通过 BCrypt 保存。
- PR 评审安全整改：公共图片仅接受经扩展名、MIME、文件头和尺寸校验的 JPEG/PNG/WebP，并强制正确响应类型与 `nosniff`；临时文件失败即清理。
- PR 二轮评审公共图片整改：新增独立公共图片组件，轮播图、新闻、团队头像和风采照片统一接收不可变暂存凭证，不再把材料分片组件或凭证对象当图片 URL 使用。
- 公共图片采用“按用户暂存 → 保存业务记录时转正”生命周期；支持 24 小时过期清理、每人 50MB/10 文件暂存配额、取消上传清理，以及替换或删除业务记录后的物理文件清理。
- PR 三轮评审永久配额整改：每个上传账号默认最多 100 张/500MB 正式图片，通过数据库原子账本记录所有者和真实字节数，多实例并发不能绕过；删除图片会释放额度，上传前还会保留至少 1GB 全局磁盘余量。
- PR 四轮评审正式接口整改：依赖 PR #12 的 `/team-content/members`、`/team-content/photos` 及审核状态流转已接入统一生命周期。PENDING、REJECTED、ARCHIVED 文件保持私有但继续占用配额，PUBLISHED 才进入公开目录，只有彻底物理删除才释放配额。
- 公共图片账本改用稳定 `asset_id`；审核搬移文件时只更新路径，不会因路径变化丢失所有者、大小或配额记录。
- 轮播图、新闻和用户图片替换先对业务行执行 `SELECT ... FOR UPDATE`，同一条记录的并发替换和纯文字更新串行化，避免旧图孤儿或配额误释放。
- PR 五轮评审删除竞争整改：轮播图、新闻、用户的删除也读取同一加锁行；批量用户及旧团队图片删除按稳定 ID 顺序加锁，删除与替换不会再使用锁前路径快照。
- PR 六轮评审公共图片迁移整改：新增管理员预检与维护窗口迁移接口，统一扫描团队风采、轮播图、新闻和用户图片；迁移读取物理文件真实字节数并重建精确配额，数量及总字节数必须同时与业务引用、资产账本、磁盘文件一致。共享路径、缺失/空文件、未知所有者、非标准路径、孤儿记录或孤儿文件都会阻止迁移，迁移开关默认关闭。
- PR 七轮评审课件封面边界整改：课件封面继续由课件模块独立管理，不进入四类公共图片配额；预检排除 `images/materials/` 命名空间，并读取有效 `course_detail.cover_path`/历史 `thumbnail_url` 精确保护根目录旧封面。被排除封面不计入四类数量或字节一致性，若与四类业务共享同一物理文件则仍会阻断。
- 团队视频/附件新增账号级 50 个/2GB 和服务器级 2000 个/20GB 原子账本；Multipart 解析前及正式复制前同时检查临时目录与上传目录的磁盘余量，所有审核状态和归档状态都继续占额度。
- PR 六轮评审附件上传整改：在读取 Multipart 请求体前完成 Token 和角色校验，通过数据库全局协调行原子登记跨实例在途容量；相同磁盘只计算一次预留，默认限制全站 4 个并发上传、每账号每分钟 12 次，并通过 120 分钟过期时间回收异常中断的预留。
- 附件上传在同一事务内先锁定 IMAGE/WORD 父内容，再检查容量、占用额度和保存附件；父内容归档也使用相同父行锁，避免上传与归档并发时生成归档内容下的新附件。
- 图片和附件物理删除统一进入 `file_deletion_task`：任务保存稳定资源编号、路径、所有者、大小、重试次数、最后错误和下次重试时间，支持定时退避、管理员查询/手动重试以及“文件已不存在”的幂等收敛。
- 私有团队图片预览改为 Axios 携带 Authorization 下载 Blob，再创建页面内对象 URL；完整 8 小时登录 JWT 不再进入查询字符串。照片保存成功后会只触发一次父列表刷新。
- PR 评审数据一致性整改：已绑定团队的账号禁止直接删除，空密码不覆盖旧密码。
- 账号删除竞态在用户服务内转换为专用提示；其他数据库完整性冲突使用通用提示，不再误报“账号无法删除”。
- 前端直接依赖已在兼容主版本内升级，并移除与 Vite 7 peer 范围冲突且未使用的 Vue DevTools 插件。
