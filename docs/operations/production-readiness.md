## 最小权限数据库账户

应用账户仅应拥有本应用 Schema 的 `SELECT, INSERT, UPDATE, DELETE`（以及发布版本必要的执行权限）。DDL/备份/恢复使用单独的受控运维账户，不把运维凭据写入 systemd 环境文件。

部署前由数据库负责人根据实际 Schema 和迁移策略审核以下原则，而不是直接复制到生产：

```text
应用账户：仅 ganlu.* 的最小业务读写权限
迁移账户：仅维护窗口临时授予 ALTER / CREATE / INDEX
备份账户：仅在备份节点授予一致性备份所需权限
```

## HTTPS、代理和日志检查

1. HTTP 请求应返回到固定的 HTTPS 主机名，不使用不受控的 `Host` 重定向。
2. TLS 仅启用 TLS 1.2/1.3；证书续期后再次执行 `nginx -t` 和一次受控重载。
3. 从外网验证 API、SPA、公开图片、登录、限流和 `X-Request-Id`；确认私有课件/隔离目录返回 404 或鉴权拒绝。
4. 为应用文件日志启用 `deploy/logrotate/ganlu`，保留至少 180 天；同时配置 journald 或集中日志的等效保留期。
5. 检查日志不包含 Authorization、密码、完整请求体、证件、手机号或上传原件路径。

## 备份与恢复演练

每次演练都应有负责人签字的记录，至少包括：

1. 备份一个时间点的 MySQL 数据和受控上传根的清单（不把样本材料提交仓库）。
2. 在隔离环境恢复数据库和上传根，启动应用并完成只读健康检查。
3. 验证账户登录、课件鉴权、审核记录、举报/隐私工单、保全审计和上传扫描状态的一致性。
4. 模拟一项恢复失败，验证不会把隔离目录或未扫描文件公开。
5. 记录 RPO/RTO、发现的问题、修复负责人和复验日期。
